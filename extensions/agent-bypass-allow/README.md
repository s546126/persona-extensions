# Bypass auto-allow (Claude Code & Antigravity CLI)

> **Category: Public extension** — General-purpose extension using only public Persona extension APIs; credentials and user data stay strictly in installed settings and local extension data.

Claude Code (`bypassPermissions`) and Google Antigravity CLI (`agy`, `toolPermission: "always-proceed"`) in bypass mode still stop on some calls, such as a read outside the working directories or a command with a dynamic target, and an unattended agent waits there. On the computers you choose, this extension installs a local hook (`PermissionRequest` for Claude Code, `PreToolUse` for `agy`) that allows those calls for Bash (`run_command`), the read-only tools (`Read`/`read_file`/`view_file`, `Glob`/`find_by_name`, `Grep`/`grep_search`, `LS`/`list_dir`, `NotebookRead`) and subagents (`Agent`/`invoke_subagent`), only in bypass sessions. For Claude Code, Persona assistant channel profiles are discovered and kept up to date automatically, alongside the default `~/.claude` and any additional configured directories. Commands that delete or overwrite data still ask, unless every target is in a temporary or work directory (`/tmp`, the session's working directories, `~/ag-work`, `~/wt`, Claude Code's worktrees) or the "Auto-allow deleting and overwriting too" setting is on. Version 0.2.34 keeps agy assistant writes working when ACP `additionalDirectories` add the current conversation's Persona supervision directory (in either supported layout under the agy directory) or an exact `~/.persona`/`~/.jarvis` `runtime-packages/persona-antigravity-runtime/<64 lowercase hex>` directory to `workspacePaths`; these extra roots do not replace the required assistant workspace or become writable themselves. Unrelated project workspaces and other sessions' directories still ask. Version 0.2.32 covers shell-parser confirmations, including zsh `${(P)k}` probes and statically resolved indirect scratch targets. Known root/home deletion targets, dynamic executables and evaluated zsh expansions still ask even with that setting on. Force pushes, permission changes, every other tool, and your own ask and deny rules always ask. Each allow is logged with the command cut and secrets masked. A separate setting, off by default, also allows `Write`/`write_file` and `Edit`/`edit_file` from Persona's main and supervisor conversations into listed directories (`~/.jarvis/assistant`, `~/.persona/assistant`).
