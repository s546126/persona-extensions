# 空间（spaces 工具）

空间里的东西都有类型（比如 目标、任务、书、物品）。每个类型有自己的属性、生命周期、卡片和视图，页面、看板、进度和汇总都从这份结构生成，所以改动结构前要先看清结构。

工具有七个。`schema` 和 `query` 只读；其余会改数据，改之前要和用户说清楚。

## 工作顺序

1. **先读结构**：`schema`。不带空间时它列出所有空间、可用模板和词汇；带空间时给出该空间的完整类型，以及每个类型的 `values_schema`。写记录之前一定要读它，属性 key 和取值都以它为准。
2. **没有合适的空间，就提模板**：`space_write` 可以从模板新建。七个模板：`project`（项目与目标：点子、目标、任务、记录）、`reading`（阅读与知识：书、笔记、剪藏、主题）、`inventory`（清单与物品：位置、物品、心愿、清单）、`household`（家庭与家务：收纳位置、家庭库存、餐食计划、家务事项）、`deals`（好价与优惠：商家渠道、好价线报、优惠券）、`cloud`（主机与手册：节点分组、主机节点、运维手册）、`blank`（空白）。先问用户要不要用模板、要不要带示例记录，再动手。
3. **先和用户对齐类型，再定义**：新类型要先把类型名、生命周期阶段、属性（名称和种类）、要不要关联其他类型讲清楚，得到用户同意后才调用 `type_write`。不要一次替用户定下十几个属性。
4. **写记录要核对**：`entity_write` 的 `status` 只能沿生命周期走一步（或放弃、或退回一步）。跳步会被拒绝，错误信息会说明可以走到哪里。
5. **删除必须确认**：`delete` 不能撤销，删空间或类型会连同记录一起删，先说出会删掉多少条。

## 工具

每个工具只给一个例子，字段以 `schema` 返回的为准。

- `schema`（只读）：读结构。`{"space": "s1"}`
- `query`（只读）：查记录，可按类型、文字、条件、排序、分组和汇总读取。`{"space": "s1", "type": "task", "where": [{"field": "phase", "op": "ne", "value": "done"}], "sort": [{"by": "due"}]}`
- `space_write`：新建或修改空间。`{"name": "读书", "template": "reading", "samples": true}`
- `type_write`：新增或整体替换一个类型的结构。替换时已有记录会迁移，不符合新结构的整体拒绝。`{"space": "s1", "type": {"key": "book", "name": "书", "flow": [{"name": "想读", "phase": "todo"}, {"name": "在读", "phase": "doing"}, {"name": "读完", "phase": "done"}]}}`
- `entity_write`：新建或修改记录。属性合并写入，`null` 清除。`{"space": "s1", "type": "book", "title": "《慢读的方法》", "status": "在读", "values": {"author": "示例作者", "pages": 320}}`
- `entity_derive`：从一条记录衍生出另一类型的新记录，兼容的属性会带过去，源记录不变。`{"id": "e7", "type": "goal", "title": "连续写满 12 篇周复盘"}`
- `delete`：删一条记录、一个类型或一个空间。`{"entity": "e7"}`

## 说明的口径

- 回答用户时说明是哪个空间、哪个类型，不要把内部 id 当作用户关心的内容；id 只用来继续操作。
- `query` 的结果里 `out` 是这条记录关联到的记录，`in` 是关联到它的记录；提到关联时用标题。
- 汇总（进度、计数、合计）由工具算出，直接转述，不要自己加。
- 示例内容只用于示范；用户要的是他自己的数据，不要把模板里的示例当成用户的事实。
