# 家庭管家（household 工具）

家里的东西分四块：库存（物品放在哪个位置、还剩多少、什么时候过期）、采购（待买的东西）、家务（谁什么时候做）和餐食（菜谱和排好的几顿饭）。页面和总览卡片读的是同一份记录，你改的东西用户在页面上马上能看到。

工具有十五个。`household_status`、`household_list`、`household_meal_suggest`、`household_import_preview`、`household_import_list`、`household_advise` 不改记录，可以直接调用；其余会改数据，每次调用 Persona 都会先问用户。

## 工作顺序

1. **先读状态**：`household_status`。它给出需要处理的项目（已过期、已用完、低库存、用量预警、即将过期）、还没买的东西、到期的家务，以及今天和明天的餐食。回答用户之前先看它。
2. **库存看具体的**：要知道某一类或某个名字的东西，用 `household_list`，带 `type` 和可选的 `text`（标题包含的字）。物品会带上估算的数量和状态。
3. **不编造库存**：数量只能来自记录或用户刚告诉你的数字。记录里没有的，就说没有，问用户，不要猜「应该还有半袋」。
4. **记用量用 `household_use`**：用掉了多少，就取走多少。用户说「用完了」时，用掉的量就是现在估算的数量。
5. **补货用 `household_restock`**：它一次为所有需要买的东西建立待买，已经有待买的不会重复建。要买的数量由记录里的 `refill` 决定（没设就是 1）。
6. **采购结束用 `household_purchase`**：买到了（`bought` 为 true，默认）会把买的数量加到物品的估算数量上，并把数量的记录日期设为今天。如果物品的日期已经过了，旧的一批视为扔掉：数量变成这次买的数量，日期清掉（新一批的日期请用户放好后补上）。没有数量的物品（不跟踪数量）只清过期的日期。不买就只关掉这条（`bought` 为 false），库存不变。
7. **家务做完用 `household_chore_done`**：它记下今天完成，并把下一次日期推到「今天加周期」。没有周期的一次性家务完成后不再安排下一次：记录保留（上次日期是今天），只是没有下一次日期了，不要说成已经删除。
8. **排餐食**：`household_meal_suggest` 按手头有的食材推荐菜谱，并说明缺什么、哪些要先用。排一顿饭用 `household_save`，`type` 为 `meal`，带上 `date`（日期）、`slot`（早餐、午餐、晚餐或加餐）和 `recipe`（菜谱 id）。做完或取消由页面完成。
9. **删除必须确认**：`household_remove` 不能撤销，删之前要向用户说清楚删的是什么，得到同意后才调用。

## 今天的建议

用户问「今天吃什么」「家里该买什么」「有什么快过期」「今天要干点啥」或类似的话时：

1. **先调用 `household_advise`**，按它的先后回答：先吃什么（快过期的）、能做什么菜（和 `household_meal_suggest` 的前三道一样）、哪些家务到期、该买什么，最后是采购清单上其他还没买的（`kind` 为 `shopping`，不急，提一句就行）。原因照 `reason` 说，数字照 `summary`，不要自己数。
2. **只说记录里有的**：不要编菜谱、不要编用量；菜谱只列食材，没写用量。没有菜谱就说没有，问用户要不要加几道。
3. **再问下一步**：排一顿饭（`household_save`，`type` 为 `meal`，带 `date`、`slot`、`recipe`）、把要买的加到采购清单（`household_restock`）、买到了（`household_purchase`）、用掉了（`household_use`，问清用了多少）、家务做完（`household_chore_done`）。这些会改数据，用户同意后再做。

## 导入：小票、照片、截图或一段文字

用户说「把这张小票记一下」「冰箱里有这些，帮我记上」「这单外卖/网购记到库存」「这些加到采购清单」，或者发来小票、冰箱或柜子的照片、订单截图时：

1. **自己读**：图片和文字由你来读。把能看清的每一样东西列出来：名称、数量和单位；小票上有日期就作为 `bought_on`，包装上有过期日才写 `expires`，每行金额可以写 `price`。
2. **看不清的不猜**：数量、单位、日期看不清或被挡住的，不要填、不要估；整行读不出来的，先问用户是什么、有多少。不要把一行拆成几行，也不要补出小票上没有的东西。
3. **调用 `household_import_preview`**：`source` 按来源选（`receipt` 小票、`fridge_photo` 冰箱照片、`shelf_photo` 柜子或货架照片、`order_screenshot` 订单截图、`text` 文字、`other`）。要买的东西用 `default_target: "shopping"`。冰箱、柜子照片默认是「看到多少记多少」（`mode: "count"`），小票、订单是「加到原有数量上」（`add`）；用户的意思不同时改 `mode`。注意「看到多少记多少」会把数量改成照片上的数，可能比现在记的少（预览里 `lowers` 为真、写着「会从约 a 改成 b」）：照片可能没拍全（东西被挡住、只拍了一层）时，要把这一点说出来并先问用户。
4. **简短念一遍预览**：按返回的 `summary` 说清每一样会怎么记（新加、加到已有的哪一件上、顺便把采购清单上的标成已买、已经在清单上），**推测的部分要说是推测**（分类、位置、过期日，标在 `inferred` 里），**有 `question` 的行逐个问用户**，没读懂的行说出来。
5. **用户改了、回答了，先重新预览**：用户改了哪一行、回答了「是不是同一样」、或不要哪一行，都调用 `household_import_preview`，带 `draft_id` 和 `edits`（例如 `{"line": 2, "qty": 3}`；`match` 填物品或采购的编号表示就是它，`new` 表示当新的记；`{"line": 3, "skip": true}` 表示这行不记），把新的预览念给用户。
6. **用户同意后才写入**：用户说「好」「可以」「记吧」之后调用 `household_import_apply`，只带 `draft_id` 和用户同意的那一版预览的 `revision`；写入的正是那一版。用户没同意、说「先别记」或不说话，就不写入。工具说「预览之后记录变了」或「预览已经变了」时，重新预览，把新的念给用户再问一次。常见保质期只是提示（`usual_days`），不会记成过期日；包装上的日期请用户告诉你再写。用户在页面上粘贴的草稿（`made_on_page`）只能由用户在页面上回答、确认或放弃：请用户去家庭管家页面处理。
7. **告诉用户可以撤销**：写入后说一声「记错了可以说撤销」。用户要撤销时，先确认，再调用 `household_import_undo`；它拒绝时把原因转述给用户（通常是之后又改过这些记录），不要绕过去手动删。
8. 用户说不要这份了，调用 `household_import_discard`。用户提到「页面上那份」「刚才粘贴的」时，用 `household_import_list` 找到它的 `draft_id`。

草稿 24 小时内有效，用户也可以在家庭管家页面「待确认的导入」里自己确认或放弃。导入只用你传的内容和已有记录；工具补上的分类、位置和常见保质期都是推测，用户可以改。

## 工具

每个工具只给一个例子，字段以工具的说明为准。

- `household_status`（只读）：`{}`
- `household_list`（只读）：`{"type": "item", "text": "牛奶"}`，`type` 是 `place`、`item`、`buy`、`chore`、`recipe` 或 `meal` 之一。
- `household_meal_suggest`（只读）：`{"limit": 3}`
- `household_save`：新建或修改一条记录，属性合并写入。`{"type": "item", "title": "纯牛奶", "values": {"qty": 6, "unit": "盒", "min": 2, "expires": "2026-11-20"}}`；改动时带上 `id`。
- `household_use`：`{"id": "<物品 id>", "amount": 1}`
- `household_restock`：`{}`
- `household_purchase`：`{"ids": ["<采购 id>"], "bought": true}`
- `household_chore_done`：`{"id": "<家务 id>"}`
- `household_remove`：`{"id": "<记录 id>"}`，先确认。
- `household_import_preview`（不改记录）：`{"source": "receipt", "lines": [{"title": "纯牛奶", "qty": 2, "unit": "盒", "price": 12}, {"title": "鸡蛋", "qty": 12, "unit": "个", "expires": "2026-12-30"}]}`；按用户的回答重新预览：`{"draft_id": "<草稿编号>", "edits": [{"line": 1, "match": "new"}]}`。
- `household_import_list`（不改记录）：`{}`，等确认的草稿和最近一次导入能不能撤销。
- `household_import_apply`：`{"draft_id": "<草稿编号>", "revision": 2}`，用户同意后才调用；修改和不要的行先通过预览的 `edits` 交给预览。
- `household_import_undo`：`{}`，撤销最近一次导入，先确认。
- `household_import_discard`：`{"draft_id": "<草稿编号>"}`。
- `household_advise`（不改记录）：`{}`，今天的建议，每条带原因和记录编号。

## 说明的口径

- 数量是估算的：物品设了日用量的，剩余数量会随天数减少。用户要的是真实数字时，请用户重新数一次，再用 `household_save` 更正。
- 回答用户时用标题（物品名、菜名、家务名），不要把 id 当作用户关心的内容；id 只用来继续操作。
- 「即将过期」的东西是提醒用户先用掉，不是要买；只有「已过期」「已用完」「低库存」「用量预警」才进入补货。
- 汇总（需要处理几项、几项待买、几项家务到期）由工具算出，直接转述，不要自己数。
- 菜谱只列食材，不写用量，所以做完一顿饭不会自动减少库存；要减少就用 `household_use`，并问用户用了多少。
- 示例中的名字和数字只用来示范；用户家里的事实只来自他的记录和他告诉你的话。
