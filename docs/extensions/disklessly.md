# Disklessly

[Documentation](../README.md) · [Source](../../extensions/disklessly/)

Disklessly connects multi-machine disk watermark inspection, rebuildable developer cache cleanup, and coding-agent cold session archiving to Persona's machine management. It manages the local computer alongside remote SSH hosts discovered from `~/.persona/config.json`, `~/.ssh/config`, or added from the extension page and MCP tools.

All state is stored locally in the extension's data directory as `disklessly_state.json`, shared between the hub extension process and `disklessly mcp` over stdio.

## Machine discovery and fleet watermarks

On startup and on demand, Disklessly merges machines from:

1. **This machine (`local`)**: always present and enabled first.
2. **Persona machine configuration**: `~/.persona/config.json` and `~/.config/persona/config.json` (`machines` or `nodes`).
3. **OpenSSH client configuration**: concrete `Host` blocks in `~/.ssh/config` (wildcard patterns such as `*` apply as defaults; negated or wildcard tokens are skipped).
4. **Manual SSH nodes**: added or edited from the page or with `disklessly_machine_upsert`.

Each machine's root volume (`/System/Volumes/Data` on macOS, `/` on Linux) is evaluated into a health watermark:

| Level | Condition | Badge & progress bar |
| --- | --- | --- |
| `ok` | Reachable and below warning thresholds | Green (`positive`) |
| `warning` | Used ≥ 80% or free < 25 GiB (on ≥ 50 GiB disks) | Orange (`caution`) |
| `critical` | Used ≥ 90% or free < 10 GiB (on ≥ 20 GiB disks) | Red (`danger`) |
| `offline` | Last SSH probe failed | A neutral 连不上这台电脑 badge and a wifi icon (with when a check found that, when known), never a fullness colour; a computer checked before keeps its last check's fullness on its bar and badge (marked 上次, with the check's date on its row) |

## Scan categories and safety redlines

A scan runs a single read-only POSIX shell probe locally (`/bin/sh`) or over OpenSSH (`BatchMode=yes`, `ConnectTimeout=12`). When the target host has the `disklessly` CLI installed (looked up in `$DISKLESSLY_BIN`, then `PATH`, then `~/.disklessly/bin/disklessly`, `~/.local/bin/disklessly`, `/usr/local/bin/disklessly`, `/opt/homebrew/bin/disklessly` and `/Applications/Disklessly.app/Contents/MacOS/disklessly`; see [Install the disklessly CLI](#install-the-disklessly-cli)), its version is recorded and the probe also reads `disklessly --json sessions` (the CLI's own cold-session plan), `disklessly --json sessions status` (backup backend reachability, index counts and archived bytes). After every successful scan of a machine with the CLI, the extension refreshes that machine's cold index (see below). Without the CLI the built-in shell probe still measures caches and estimates hot and cold sessions, but cold sessions are not archivable.

The probe has 90 seconds. It reads the root volume first and sizes caches after it, so a machine whose caches take longer to size (a large Go module cache or `~/.npm`) still gets its watermark: the scan is kept as partial (`partial` and `partial_reason` on the scan, `partial` on `disklessly_machines_status`), the page and the overview card say the caches were not fully sized, the items and totals cover only what was sized in time, and the cold index is not refreshed from it. When the time is up, the shell is killed and the run returns within a few seconds even if a `du` or `find` it started is still running. A probe that stopped before its `df` line was complete has no watermark and fails as before.

| Category | ID | What it probes | Safety |
| --- | --- | --- | --- |
| Go build & module cache | `go-cache` | `GOCACHE` (`~/.cache/go-build`) and `GOMODCACHE` (`~/go/pkg/mod`) | `safe` |
| Node & Python caches | `node-python-cache` | `~/.npm`, `~/.local/share/pnpm/store`, `~/.cache/pnpm`, `~/.cache/yarn`, `~/.cache/pip`, `~/.cache/uv` | `safe` |
| Docker unused artifacts | `docker-unused` | Dangling images (`dangling=true`) and unused BuildKit build cache (`docker system df`) | `safe` |
| Rust, Xcode & compiler caches | `rust-xcode-build` | `~/.cargo/registry`, `~/.cargo/git`, `~/Library/Developer/Xcode/DerivedData`, `~/.cache/org.swift.swiftpm`, `~/.cache/clang`, `~/.gradle/caches`, and `~/.cache/ms-playwright` (`review`) | `safe` / `review` |
| System logs & stale `/tmp` | `tmp-logs` | `journalctl` logs older than 7 days, rotated `/var/log/*.gz` / `*.1` / `*.old`, and `/tmp` build/test directories older than 7 days | `safe` |
| Cold coding-agent sessions | `cold-agent-sessions` | Claude Code (`~/.claude/projects`) and Codex (`~/.codex/sessions`) transcripts the `disklessly` CLI plans to archive (idle over 7 days, not open, not excluded) | explicit only (uploaded, then removed) |

### Safety redlines

- **Running containers are never touched**: only dangling images and unreferenced BuildKit caches are cleaned.
- **Active git repositories and uncommitted changes are never touched**.
- **Cold sessions are archived only by the `disklessly` CLI**: the cleaner runs `disklessly --json sessions --apply --days 7 --exclude-from <list>` once (the scan's plan is `disklessly --json sessions --days 7`; the 7-day threshold is always passed, so the CLI's own default does not apply) and never deletes a transcript itself. The CLI uploads each session to the backup backend and removes the local copy only after the upload is committed. Hot sessions (modified within 7 days), open sessions and excluded sessions stay in place. There is no local tar fallback: if the CLI is missing, the backend is unreachable (exit 4, `backend unreachable`) or the run fails, the clean reports an error and no session is uploaded or deleted. The page offers archiving only when the last scan found the CLI and a reachable backend. Because sessions leave the machine, they are never part of a generic safe cleanup (**删掉放心删的缓存**, the plan's run-all-safe button, or `disklessly_clean` without `categories`/`items`) and do not count in the safe totals; they run only when `cold-agent-sessions` or a session item is named, or through **把一周没动的 AI 对话搬到网盘** / `disklessly_sessions_offload`. One CLI run covers every agent (Claude Code, Codex, pi, Gemini, Qwen, …), so naming one session item selects them all, and archives of agents without a scan item are recorded as `sessions-cold-other`.
- **Referenced sessions are excluded**: `disklessly_clean` and `disklessly_sessions_offload` accept `exclude_sessions` (absolute transcript paths or session ids: the Claude file stem or the trailing UUID of a Codex rollout file). They are combined with the target machine's optional `~/.disklessly/session-excludes` file and with the reference probe's findings, passed as `--exclude-from`. The extension builds this list once, before the CLI starts; the CLI then re-reads the exclusion list and runs its own scan of running processes and herdr's `session.json` right before each local delete, so a session that becomes referenced during the run is still kept.
- **Reference probe (fail closed)**: once, before `--apply` starts, a POSIX shell probe on the target machine (Linux and macOS, also over SSH) adds every session something still uses: session UUIDs after `--resume`, `-r` or `--session-id`, and every UUID in a `claude` or `codex` command line (so `codex resume [OPTIONS] <id>` and `codex exec resume` count), in running processes (`/proc/*/cmdline` on Linux, `ps -axww -o pid= -o args=` on macOS); for a `claude` or `codex` process without a session id in its argv (`claude -c`, the `--resume` picker, `codex resume --last`), every transcript of its working directory (`/proc/<pid>/cwd` or `lsof -d cwd`): the Claude project folder for that cwd and the Codex rollouts whose `session_meta` names it; every open `*.jsonl` (`/proc/*/fd` on Linux, `lsof -u <uid>` on macOS); and every UUID and absolute `*.jsonl` path in `~/.config/herdr/session.json` (where Persona keeps resumable agents as `agent_resume` argv `--resume <id>`) and in `herdr pane list` (5 s limit, only when `herdr` is on `PATH`). The probe adds what the CLI's own pre-delete check does not cover (open files via `/proc/*/fd` or `lsof`, `herdr pane list`, the caller's `exclude_sessions`); it does not run again during the CLI run. Over-inclusion only keeps a file local. If neither `/proc` nor `ps` can list processes, the run stops before the CLI starts and nothing is uploaded or deleted. The number of sessions kept as referenced is recorded in the history ledger.
- **Credentials and keys are strictly refused**: `CheckSafeCleanTarget` blocks system roots, user home roots, `~/.ssh`, `~/.gnupg`, `~/.aws`, `~/.persona`, and `~/.disklessly/keys`.
- **In-use process guard**: before deleting cache children, the cleaner checks running toolchain processes (`go`, `gopls`, `pnpm`, `npm`, `cargo`, `rustc`, `swift`, `clang`, `xcodebuild`, `pip`, `uv`, `GradleDaemon`) and `/proc/*/maps` / `/proc/*/exe`, skipping any entry in use and reporting it as `@@BUSY`.

### Cold-session backup and search

The **AI 对话** page has a search box (`搜对话：标题、第一句话、项目或关键词`; every word must match, and a time word among them, 今天 / 昨天 / 前天 / 这周 / 上周 / 本月 / 上个月 / 今年 / 去年, keeps the conversations last changed in that time; 搜全文 still sends the words as typed; the results' footer says so), an intro saying what moving conversations does (upload, read back and verify, then delete the local copy; conversations in use stay), the status (conversations indexed, in the network drive, 还没核对过 — not confirmed by a check of the last 24 hours, the rows' badge says the same, while MCP answers keep the value `暂时不确定`, never a loss —, 网盘里找不到 — recorded as moved but its segment is missing —, with a note under them, when either is not zero, on what each means and the button that checks again, last check, and the computers counted as `2 台正常 · 3 台要处理`), a line saying which computers can move conversations now and where the button is, with the states of the others (`其余 3 台还不能搬（1 台连不上这台电脑、1 台还没装配套小工具、1 台还没设置网盘）`), a short read-only **帮我腾空间** block (the `move_conversations` steps of `disklessly_advise` for at most three computers, the ones that can be done now first, each with what it frees and where its button is or why it cannot be done now; tapping one picks that computer; then a sentence to say to the Persona assistant, which finds a conversation from a description with `disklessly_sessions_find`), one row per computer (below), **重新检查所有电脑** (under 全部电脑) and, with a query, **搜全文**, and the results. Each ready computer's row carries **把一周没动的 AI 对话搬到网盘**, so it is reachable from 全部电脑; a computer that is not ready gets its reason instead, and an upload started on one is refused with that reason. After a failed upload the row offers **重试：搬到网盘**; a failure's text only names buttons the row draws (a failed restore points to the conversation's 拿回来, a failed file move to Persona's disk usage map). Without a query it lists the most recently archived sessions. Each result row shows a title that is never an id (the conversation's title; else the start of its first message, up to its first sentence end and at most 50 characters, when it has content; else `没有标题的对话 · <date> <time> · <assistant>`, with the first message, if any, as `第一句话：…` in the detail; a first message has no content when, after a leading `/command`, fewer than two of its words are not filler (`ok`, `hi`, `test`, `reply`, `continue`…; numbers do not count) counting two Chinese characters as a word and runs made only of 继续, 好的, 测试, 一下… as none: `reply OK`, `hi`, `继续`, `/clear`, a single word or punctuation make no title; search still finds the first message), machine · Claude Code/Codex · project (the CLI's `_unknown` reads `没归到项目`; else the last folder of the working folder) · the working folder's last folder when it is not the project · date and time (not repeated for an untitled one) · size, the first prompt and the session id (`对话编号 …`, which search also finds), and a location badge; rows not already local have a **拿回来** action that restores the transcript to its original path and shows the resume command (`claude --resume <id>` or `codex resume <id>`). Page state holds only the machine and the query.

**One state per machine.** Each refresh classifies what it found, and the page shows one row per machine, worst first, with its name (filter chips and rows show the name only, without the network address that `~/.ssh/config` discovery appends; the address stays on the machine's own page), state, and, for a computer that is not ready, a plain line of its own right under the row: what is wrong, its everyday causes (for an unreachable one: switched off or asleep, not on the same network or VPN, address or login changed) and what to do first without a terminal, naming the button on that row. The newest check of a computer, whichever page ran it, decides whether it can be reached: when it could not, both pages count it and badge it 连不上这台电脑 (the AI 对话 row adds what its own older check found, 「上次连得上时（3 天前检查）发现：…」, and a failed 硬盘空间 check is said once); when this page could not reach it and a later 硬盘空间 check did, its badge is 要重新检查. Both pages name the check button by the same rule: **检查 *computer*** before the first check, **重试 *computer*** when the newest check could not reach the computer, **重新检查 *computer*** otherwise; and they use the same words for the same fact: 连不上这台电脑 when SSH fails, 这台电脑连不上网盘 when it answers and its drive does not. A drive problem's line says how many of that computer's conversations it leaves 还没核对过 (the count at the top includes them), or that none is. Each page says when its own check ran. Times are written one way on every page: 「刚刚」「5 分钟前」「3 小时前」「3 天前」 within a week, then 「11月14日」 (with the year when it is another year), and a conversation's or a clean-up's time adds the time of day once it is a day old. The 硬盘空间 page says the same under a computer whose last check failed. Below it come the buttons that fix it and **详情**, then, last, a command to copy (a `code` block) when one helps, introduced by a line saying where to run it (for example 懂终端的话，可以在运行 Persona 的电脑上试这条命令看具体报错：). **详情** opens the raw text: OpenSSH's last line, the CLI's answer, Homebrew's output or a failed job's error. English errors and raw output never appear in the row itself; the page state remembers only which 详情 is open (`x`).

**In the hub's sandbox.** An extension installed from a local package (for example `personad extension upgrade disklessly file:…`) runs in the hub's sandbox unless it comes from a trusted market. The sandbox has no network, sets `HOME` to the extension's data directory and maps file owners so that OpenSSH refuses `/etc/ssh` (`Bad owner or permissions on /etc/ssh/ssh_config.d/…`): no SSH machine can be reached and the local results are not the user's. The extension recognises the sandbox (its hub address is `hub.persona.internal`, which only the sandbox's egress proxy serves), shows a first section on both pages saying so, and words every unreachable machine as such, with the command `personad extension sandbox disklessly off` (run on the hub; `default` turns the default back on).

The state is stored with the cold index (`state`, `cause`, `detail`, the CLI's version and install location, the platform); indexes written by earlier versions have no state and are classified from their error text and backend fields when read.

**Background jobs.** The hub gives a UI request about 12 seconds, while a refresh may take minutes per machine. **重新检查所有电脑** and the per-computer buttons therefore start the refresh in the background and return at once: machines run in parallel (at most four jobs at a time), and one machine never has two jobs at once; tapping again while it runs only says it is already running. Restore, upload (**把一周没动的 AI 对话搬到网盘**), Homebrew install and copy-install run the same way; their outcome (or the reason they failed, with the raw text under 详情) is shown under the machine's row. On the 硬盘空间 page, **检查**, **检查所有电脑（只看不删）**, **删掉放心删的缓存**, the category and item cleanups and **按勾选的种类删除** are background jobs too (a scan may take 90 seconds, a cleanup minutes): the toast says it started, the machine's section shows what runs and then how it ended, and the history ledger gets the record when the cleanup is done. A failed probe is drawn under the machine as on the AI 对话 page (cause, next step, command, 详情), and the overview card shows its short cause. The manifest asks to be started with the hub (`activation_events: ["on_startup"]`): a page-only extension is otherwise stopped after ten idle minutes, which would end a long job and its SSH session with it. A job works on a private copy of its machine's state without holding the store lock, so the page keeps drawing, and merges its result under the lock when it ends. While a job runs, the row says what is being done, the status names the computers and what runs on each (`正在进行：「…」把一周没动的 AI 对话搬到网盘`), a finished upload says how many conversations moved, the space freed and how many in-use ones stayed, and the view asks to be drawn again (`refresh_after` 30 s); the extension also sends `ui.invalidate` as each job ends, so pages on screen update at once on hubs that support it. Job state is kept in memory only. **搜全文** stays in the request: it asks the machines in parallel, at most 8 seconds each, and names the machines that did not answer in time.

**Local cold index.** After a scan, after an offload and on refresh, the extension runs `disklessly --json sessions list --state all --limit 5000` and `disklessly --json sessions status --check-segments` on the machine (a scan does so only when the index is older than six hours; refresh and offload always do), plus `sessions list --state all --digest --limit 5000` only when the index has rows it has no keywords for yet, and stores, per machine, the backend (`id`, `type`, `reachable` — unknown when the check failed —, latency, error, check time), the missing and unchecked segments, and up to 5,000 entries, newest first (`capped` is shown when the status counts are higher): id, session id, tool, path, cwd, project, month, mtime, archive time, bytes, state, title (≤120 characters), first prompt (≤240 characters), segment, and up to 16 keywords extracted locally from the digest (Latin and digit words of 3 to 24 characters without stopwords and hex-like hashes, CJK runs clipped to 2–6 characters, by frequency). The digest itself is never stored.

**Location.** `在网盘里` (in the network drive) needs state `archived` or `remote` (or `pendingDelete` when its segment also holds an `archived` or `remote` row, since only those segments are checked), a backend check from the last 24 hours that found it reachable, a known segment that is neither missing nor unchecked, and a reachable machine. `网盘里找不到` means the segment was reported missing; `还在电脑上` means `restored` or `keptLocal`; anything else (backend unreachable or unchecked, never or not recently checked, machine offline) is `暂时不确定`, which is never treated as absent. Earlier versions used `在云端` / `云端缺失` / `本地` / `未知` for the same four values.

**Search.** Every whitespace-separated token must occur, case-insensitively (CJK as a substring), in the title, first prompt, keywords, cwd, project, path, session id, tool, machine name, stored name or host name (the hub's own computer is shown as 运行 Persona 的电脑, but searching its host name still finds it, and the MCP tools accept that label back as `machine`); results are newest first. Queries are cut to 200 characters. Another device's rows (state `remote` after `sessions reindex`) are shown only under their own machine when it is managed here, and are marked 来自另一台电脑. **搜全文** (and `deep: true` over MCP) also runs `disklessly --json sessions search WORD… --limit N` on the machines (leading dashes dropped, since the CLI reads them as options) and merges the hits by entry id. Restoring runs `disklessly --json sessions restore ID` (also for a full-text hit outside the local index), checks that the returned path is back and not empty, marks the entry local and records it in the history. Another device's row is not restored: its original path belongs to that device, so the extension points to the CLI's `--to`. The resume hint is `claude --resume <id>` or `codex resume <id>`; other agents get none.

## Install the disklessly CLI

The extension does not ship the `disklessly` CLI. On macOS and Linux, install it with Homebrew:

```sh
brew tap nwverse/tap && brew install nwverse/tap/disklessly-cli
# later: brew upgrade nwverse/tap/disklessly-cli
```

The full name matters when another tap also has a `disklessly-cli`: Homebrew then refuses the short name (`Formulae found in multiple taps`). The extension always uses the full name.

On macOS the 0.3.0 build is not notarized; clear the quarantine flag Homebrew sets before it runs (the formula's caveats say the same): `xattr -dr com.apple.quarantine "$(brew --prefix nwverse/tap/disklessly-cli)/bin/disklessly"`. Without Homebrew, install Homebrew first (<https://brew.sh>; on Linux add it to `PATH` with `eval "$(/home/linuxbrew/.linuxbrew/bin/brew shellenv)"`), or copy the CLI from another computer (below).

The page and the scripts look for the CLI in `$DISKLESSLY_BIN`, then `PATH` (an SSH command's `PATH`, which on macOS usually lacks Homebrew), then `~/.disklessly/bin/disklessly`, `~/.local/bin/disklessly`, Homebrew's keg (`/opt/homebrew/opt/disklessly-cli/bin/disklessly`, `/usr/local/opt/…`, `/home/linuxbrew/.linuxbrew/opt/…`, `~/.linuxbrew/opt/…`), then `/usr/local/bin/disklessly`, `/opt/homebrew/bin/disklessly`, `/home/linuxbrew/.linuxbrew/bin/disklessly`, `~/.linuxbrew/bin/disklessly` and `/Applications/Disklessly.app/Contents/MacOS/disklessly`. The keg comes before the shared `bin` directories because another program may own that name there, for example the Disklessly app linking its older engine as `/opt/homebrew/bin/disklessly`. The page needs a CLI that has `sessions list` and `sessions status`.

**Homebrew from the page.** Each refresh also looks for Homebrew on the machine (`brew` on `PATH`, `/opt/homebrew/bin/brew`, `/usr/local/bin/brew`, `/home/linuxbrew/.linuxbrew/bin/brew`, `~/.linuxbrew/bin/brew`). When a machine with no CLI, or one too old, has it, its row offers **用 Homebrew 安装配套小工具** (**用 Homebrew 升级配套小工具** when Homebrew installed the CLI), whose confirmation names the machine and the exact command. After confirmation a background job runs on that machine, over SSH: `brew tap nwverse/tap`, then `brew install nwverse/tap/disklessly-cli` (or `brew upgrade nwverse/tap/disklessly-cli` when Homebrew already has it), clears the quarantine flag on macOS, runs the new `disklessly version` and `disklessly --json sessions status` once, removes the formula's downloads (`brew cleanup --prune=0 -s nwverse/tap/disklessly-cli`, nothing else); a formula already at the newest version is reported as such, without a download, and re-reads the machine. When Homebrew cannot link the CLI because its `bin/disklessly` already belongs to something else, the install still counts if the keg's CLI works; Homebrew's link is left alone, and the outcome names what `bin/disklessly` is (what a terminal with Homebrew on `PATH` runs), that the extension uses the keg, and `brew link --overwrite nwverse/tap/disklessly-cli` to make the terminal use it too. If the lookup still finds another CLI first (an older one earlier on `PATH`), or does not find the new one, the outcome says so. A failure names the step (Homebrew missing, the tap, the download or install, the check) and keeps Homebrew's last lines under 详情. Copy-install is offered only to machines without Homebrew. `disklessly_cli_install` does the same over MCP.

To let the page copy the CLI to your other computers, install it on one of them as a self-contained directory, for example `~/.local/opt/disklessly-<version>-<os>-<arch>/` with the program in `bin/disklessly` (and its data in `share/`), linked from `~/.local/bin/disklessly`.

**Copy-install from another computer.** When a machine has no CLI or one that is too old, and another enabled, reachable managed machine of the same OS and architecture had a working CLI on its last refresh (state `ready`, `no_backend` or `backend_unreachable`) installed in such a self-contained `disklessly*` directory, the row offers **从 *computer* 复制过来**. Its confirmation names both machines, the version and the target directory. The job streams a tar of the source directory over SSH through the hub's extension process to the target (no size-limited copy through a script), unpacks it into `~/.local/opt/<dir>.new`, runs the new `disklessly version` and `disklessly --json sessions status` once, and only when both answer moves it to `~/.local/opt/<dir>` (an existing directory of that name is kept as `<dir>.prev-<time>`) and switches `~/.local/bin/disklessly` to it with a rename. A failure before the switch removes the staging directory and leaves the link as it was; the previous directory (and a previous non-link binary, as `disklessly.prev`) stays in place. Nothing needs root, nothing outside `~/.local` changes, and nothing is downloaded. The machine is refreshed afterwards. If the lookup on that machine still finds another CLI first (for example an older one earlier on `PATH`), the outcome says which one. A CLI that is not in a self-contained directory, such as a Homebrew install, is not copied; the row says so.

## Persona usage map (`disk_offload`)

The extension contributes the generic `disk_offload` point (`{"id": "disklessly", "name": "Disklessly", "kinds": ["file", "dir", "app"], "restore": true}`, namespace `offload`; contract in Persona's `docs/server/machine-usage-map.md`). Persona's disk usage map draws what is already offloaded on the cloud side of a computer's map, at the same scale, and offers "move to the cloud" for files, folders and apps; Persona names no product, it lists providers by their `name`. A hub that does not know the point installs the extension all the same (the item is ignored with a warning) and the rest keeps working.

Every call carries the Persona machine (`{id, name, os, online}`). It is matched to a managed machine by id, by name, by host name, and the hub's own computer by its host name; an unknown machine answers `unavailable` with a sentence saying how to add it. A Windows computer, or one Persona reports offline, is `unavailable` too. Sentences for people follow the call's `locale` (`en`, `zh-Hans`, `ja`; anything else is English); this extension's own pages stay Chinese.

**`offload.inventory`.** One script on the machine (local shell or SSH, 18 s) finds the CLI as the page does and asks it for what this computer has offloaded:

| Kind | Source | `bytes` / `stored_bytes` | Restored with |
| --- | --- | --- | --- |
| `app` | `disklessly --json status` apps not restored, with their image manifest (`<repo>/manifests/<image>.json` when the repo is a folder on the machine; `disklessly --json list` names the rest) | the image's plain size / its size in the repo; `local_bytes` is the cached image | `disklessly unpack <bundle id>` |
| `app_data` | `disklessly --json data status` rows in state `offloaded` (macOS) | recorded size | `disklessly data disable <bundle id>` (brings the data back and turns data offload off) |
| `file`, `dir` | the CLI's registry `files/offloaded.json` in its state folder, each placeholder still on disk read for its original path and stored size | original size / stored size; `stub_path` is the `.disklessly` placeholder | `disklessly fetch <placeholder>` |
| `bundle` | a file or folder of a linked bundle (`linked-bundles.json`), grouped under the bundle's name | as files | `disklessly fetch <placeholder>` |
| `session` | archived sessions of this computer from the cold index the extension already keeps (refreshed by its own jobs), grouped by tool | archived size | `disklessly sessions restore <id>` |

Rows are sorted largest first; at most 500 are returned and the rest is summed in `more`. Times are seconds since 1970. An answer is kept 30 seconds per machine and language; `refresh` asks again. No CLI, or one that does not know `offload`, answers `needs_install` with `tool` (`installed: false`, the version found, and `source`: one sentence on how it would be installed, Homebrew on that computer first, else a copy from a computer of the same kind, as the page offers). A CLI that answers it has no storage set up (and nothing is offloaded) is `needs_setup`. Apps whose manifest cannot be read (a network repo) are listed by name only and the answer is `partial`.

**`offload.run`.** At most 50 paths (`offload`) or inventory ids (`restore`). Each path is checked first, without walking it: an absolute, clean path; not a symbolic link, missing or special file; for a file or folder, the CLI's own offload policy (`FileOffloadPolicy`: inside the home folder, not the home folder, not `~/Library`, `~/Applications`, `~/.Trash`, `~/Public`, not a standard folder such as `~/Documents` itself, not inside an app bundle, not a photo or music library, virtual machine disk or download in progress, not a placeholder or next to one, not disklessly's own repo, cache or state) plus keys and credentials (`~/.ssh`, `~/.gnupg`, `~/.aws`, `~/.kube`, `~/.password-store`, `~/.docker`); for an `.app`, a Mac, under `/Applications` or the home folder, and not already a stub. Persona's manager also checks every path with its own rules before the call. With `dry_run` the answer is `{status: "ok", items: [{path, ok, reason?}], tool}` and nothing runs. Persona holds every answer to its offload schema, so the program's own refusal codes stay in the program: items carry only the `reason` sentence, and free text (names, details, errors) is clipped to the schema's lengths. Without a usable CLI and without `install`, the answer is `needs_install` with `tool`, and nothing is installed or moved; Persona shows a second confirmation naming the tool, the computer and `tool.source` and posts again with `install: true`. When every item is refused the answer is `refused` with the reasons and nothing starts; otherwise refused items are listed as `skipped` in the job. A machine already running a Disklessly job answers `refused` with the busy sentence. Persona hands the program the paths as the computer resolved them (absolute, clean).

**Jobs.** A run is a background job on that machine (the same job slot as the page's refresh, restore, offload and install: one per machine, four at once), and answers `{status: "started", job}`. Its phases in order: `install` (only with `install: true`: the page's Homebrew install, else its copy-install, then the CLI is checked again), `check` (sizes with `du`, free space with `df`), then per item `upload` and `verify` (`disklessly --json offload PATH` for files and folders, `disklessly --json pack APP` for apps; the item counts only when its placeholder or stub is in place and the original is gone) or `download` for a restore, and `cleanup` (`df` again: `freed_bytes`). `offload.job` returns `{state, phase, done_bytes, total_bytes, freed_bytes, error, items: [{path | id, status, error, bytes}]}`; a finished job can be polled for 30 minutes. `offload.cancel` stops between items: the running one finishes, the rest are `skipped`, the state is `canceled`. Inventories of the machine are dropped when a job ends.

## The MCP server

`disklessly mcp` speaks MCP over stdio (JSON-RPC 2.0, one message per line: `initialize`, `ping`, `tools/list`, `tools/call`). `disklessly --help` names `mcp`, which the manifest's `requires` checks. Set `PERSONA_DISKLESSLY_BIN` when `disklessly` is not on `PATH` or in `~/bin`.

| Tool | Access | What it does |
| --- | --- | --- |
| `disklessly_machines_status` | read, allowed | Lists all enabled machines with root volume watermarks (`ok`, `warning`, `critical`, `offline`), reclaimable bytes, session tiering summary, and cumulative freed space. Pass `refresh: true` to re-scan `~/.persona/config.json` and `~/.ssh/config`. |
| `disklessly_scan` | read, allowed | Runs a read-only probe on `machine` (default `local`, or `cached: true`), returning root mount capacity, reclaimable items sorted by size, session tiering, and the dry-run plan. |
| `disklessly_history` | read, allowed | Returns the cleanup history ledger (optionally filtered by `machine`, up to `limit`) with `df`-measured `before → after (+freed)` records and cumulative freed bytes. |
| `disklessly_sessions_search` | read, allowed | Searches the local cold index (`query` required; optional `machine`, `limit`, and `deep: true` for the CLI's full-text search), returning machine, tool, project, date, first prompt, location and the resume command. |
| `disklessly_sessions_status` | read, allowed | Per-machine cloud backup status: the classified `state` (codes as in the table above) with its label; for every state but `ready` the page's words as `message` (which machine, why) and `next` (what to do), a `command` to copy when one helps, `fix` naming the `disklessly_cli_install` method that applies, the `cause` and the raw `detail`; Homebrew's path (`homebrew`), the CLI version and platform, backend reachability and check time, indexed and total sessions, counts by location, missing and unchecked segments. `refresh: true` re-reads the index and checks the backend first. |
| `disklessly_sessions_find` | read, allowed | Finds a conversation from a description the assistant turned into hints, in the local index only (title, first message, keywords, project, working folder, dates, tool; no transcript is read, nothing is restored): `keywords` (each scored by the best field it occurs in: title 3, first message or keywords 2, project or folder 1; `match` `any` (default) or `all`), `after` / `before` (`2026-11-02`, inclusive, by the conversation's last change), `tool`, `project` (words of the project or working folder), `machine`, `location` (`on_computer`, `on_drive`, `any`), `limit` (default 10, at most 50). Candidates rank by keywords matched, field weight, then recency, and carry the page's title (never an id), date and time, tool, project / folder, computer, location, size, why they matched, the entry `id`, `can_restore` with the exact `disklessly_sessions_restore {machine, id}` call and the resume command. With no match, `too_narrow` names each hint whose removal alone would find something (and how many), and `suggest` says how to widen; it never guesses. `disklessly_sessions_search` is unchanged. |
| `disklessly_advise` | read, allowed | A ranked plan to free space, from cached scans, the conversation index and each computer's readiness only (it runs nothing that deletes or moves and reads no conversation): optional `machine`, `goal` (`free_gib`: stop once the steps possible now reach it; `fullest`: only the fullest computer) and `refresh` (default false: cached scans, each computer's `checked` says how old; true runs the same read-only probe as 检查). Fullest computers first; on each, safe cache kinds biggest first, then moving week-old conversations, then old logs and temporary files; `look_first` holds the `review` items apart and is left out once the goal is met. Each step has the computer, `action` (`clean`, `move_conversations`, `look_first`), `what`, `frees`, a one-sentence `risk`, `possible` with `blocked` / `unblock` / `unblock_call` / `command` when not, the exact existing `call` (`disklessly_clean {machine, items}` naming only that kind's safe, not-in-use items, or `disklessly_sessions_offload {machine}`), a `preview_call` for the offload, and the page's button (`page`, `page_buttons`). Also `machines` (fullness, free space, check age, why unreachable), `not_touched`, `summary` and `how_to_act`. Deterministic for the same state and time. |
| `disklessly_clean` | write, asks | Executes a cleanup plan on `machine` for selected `categories`, `items`, or all `safe` items (`include_review: true` includes `review` items; named `categories` take their `review` items too and named `items` go whatever their level; in-use items are always skipped; cold sessions only when named; `dry_run: true` previews only), measures freed space via `df`, and records the result in the history ledger. |
| `disklessly_machine_upsert` | write, asks | Adds or updates a managed SSH machine node (`host`, optional `id`, `name`, `user`, `port`, `identity_file`). |
| `disklessly_machine_delete` | write, asks | Removes a remote machine node (or disables a discovered host so it is not re-added automatically). `local` cannot be deleted. |
| `disklessly_sessions_offload` | write, asks (destructive) | Uploads `machine`'s cold sessions through the CLI with the reference probe and `exclude_sessions`; the local copy is deleted only after the upload is read back and verified. `dry_run: true` returns the plan and the sessions currently referenced. |
| `disklessly_sessions_restore` | write, asks | Restores entry `id` of `machine` to its original path and returns the resume command. |
| `disklessly_cli_install` | write, asks | Installs or upgrades the CLI on `machine`: `method: "brew"` (the default when the machine has Homebrew) runs the Homebrew install described above, `method: "copy"` copies it from a same-platform machine; then re-reads the machine and returns its new status. It works on a copy of the machine's state and takes the store lock only to save the result. |
| `disklessly_files_offload` | write, asks (destructive) | Checks `paths` on `machine` as `offload.run` does (`dry_run: true` stops there and says whether the CLI is installed), then offloads each accepted file or folder (`disklessly offload`) or app (`disklessly pack`) in the call and returns each item's outcome and the `df`-measured freed space. It never installs the CLI; without one it points to `disklessly_cli_install`. |

A tool call that fails answers with the same plain words first and, on a line of its own, `详情：` and the raw text.

## Storage

The extension and `disklessly mcp` share `disklessly_state.json` in the extension's data directory. Every read reloads the file; every write acquires an exclusive `flock` on `.disklessly.lock`, applies the change, and atomically renames a temporary file over `disklessly_state.json`. The extension watches the file every two seconds and calls `hub.Invalidate("")` when an external MCP write updates it. Each machine's cold index is a separate compact file, `disklessly_cold/<machine id>.json`, written under the same lock only when it changed and read only by the session views and tools (parsed copies are cached by file time and size).

`disklessly mcp` resolves its data directory from `--data`, else `PERSONA_DISKLESSLY_DATA`, else the path written by the hub extension to `<user config dir>/persona-disklessly/data-dir`, else `<user config dir>/persona-disklessly/data`.
